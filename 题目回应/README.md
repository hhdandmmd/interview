项目完成：公开财报获取 → 原文保存 → 结构化解析 → 清洗与版本管理 → 财务特征 → 质量检查与结果报告。另实现增量复用和简单分组回测。

| 示例 | 来源与范围 | 实际结果 |

| [真实财务处理](示例结果/财务处理/report.html) | 东方财富真实HTTP归档；茅台、美的、格力；2024—2025年输入，2025年输出 | 72份报表、72条清洗日志、180个因子位置 |
| [公开行情分组回测](示例结果/分组回测/report.html) | 十家公司的固定财务信号与腾讯后复权日线；请求区间2023—2025年 | ROE五组研究形成20个持有窗口；实际持有2024-05-07至2025-12-24 |
| [人工清洗反例](示例结果/清洗反例.json) | 单独构造的五个输入与人工预期，未进入真实财务库 | 展示空值、坏数字、负资产、极端ROE与会计恒等式异常 |

## 二、数据获取

### 1. 自行选择公开金融数据源爬取财务数据

**已实现。** 选择东方财富公开财报接口，日常配置写在根目录`config.py`。填写公司、来源和报告季度，执行`main.py`或双击`run.cmd`，自动完成采集与后续处理。

实现入口：[HTTP客户端](../src/finpipe/ingestion/client.py)、[采集编排](../src/finpipe/pipeline.py)、[简便运行入口](../src/finpipe/runner.py)。当前实际接入一个财报网站；未接入的网站在运行前报错，不伪装成多源支持。

### 2. 覆盖利润表、资产负债表、主要财务指标

**已实现。** 三个来源报表分别为`RPT_F10_FINANCE_GINCOME`、`RPT_F10_FINANCE_GBALANCE`和`RPT_F10_FINANCE_MAINFINADATA`，对应项目的`income`、`balance`、`indicator`。

来源与字段规格统一维护在[catalog.py](../src/finpipe/catalog.py)。示例分别见[利润表](示例结果/财务处理/income.csv)、[资产负债表](示例结果/财务处理/balance.csv)、[主要指标](示例结果/财务处理/indicator.csv)；同时提供Parquet。

### 3. 覆盖一定数量的公司和报告期，给出示例结果

**已实现。** 本文件夹的小样例包含3家公司、8个输入季度、3类财报，共72份实际报表；输出2025年4季度、15个特征，共180个位置。

另已真实采集冻结的沪深京50家非金融公司、2022—2025年16个季度：预期2400个报表键，取得2353条，缺47条；2023—2025年输出9000个因子位置，8482有数值、518保留NULL与原因。完整原文见[50家公司采集清单](../data/evidence/full_market_capture_20261013/manifest.json)与[独立采集统计](../data/evidence/full_market_capture_20261013/capture_analysis.json)。小示例与50家公司验收的范围分开，不拿小样例核对结果代表全市场。

### 4. 处理请求频率控制、UA等基本反爬策略

**已实现。** 请求串行执行，间隔至少1秒；设置`User-Agent`与`Referer`，校验分页和响应结构。瞬态故障有限重试，处理`Retry-After`与同来源冷却；403停止自动重复请求并保留定位信息。

实现见[client.py](../src/finpipe/ingestion/client.py)。每次尝试记录状态、请求、响应原字节及观察时间；分页中断不拼接不同会话。测试见[test_ingestion.py](../tests/test_ingestion.py)，真实36页演示归档见[manifest](../src/finpipe/resources/demo/manifest.json)。

### 5. 爬取结果持久化存储

**已实现。** 原始HTTP正文、SHA256和请求清单保存为文件；解析后的来源行、观察、清洗结果及特征保存到工作区`catalog.sqlite`。采集阶段逐页写原文与检查点，失败后已有证据仍可定位。

实现见[archive.py](../src/finpipe/ingestion/archive.py)、[storage/database.py](../src/finpipe/storage/database.py)。原文不原地修改，离线重放不改写原观察时间。示例来源摘要与本次运行信息见[运行验收](示例结果/运行验收.json)。

## 三、结构化存储与管理

### 1. 统一原始财务字段命名与数据类型

**已实现。** `FieldSpec`集中定义源字段、规范名称、单位和期间类型。例如`OPERATE_INCOME → operating_revenue_ytd`，`ROEJQ → roe_weighted_ytd`。

证券代码保留前导零和交易所；报告期统一为准确季末；金额为人民币元，百分数转小数，流动比率保留倍数。Parquet明确字符串、浮点数、日期与UTC时间类型，缺值可空。

实现见[catalog.py](../src/finpipe/catalog.py)、[cleaning.py](../src/finpipe/transforms/cleaning.py)、[exports.py](../src/finpipe/exports.py)。实际字段与公式见[本样例字典](示例结果/财务处理/dictionary.md)和[完整字典JSON](示例结果/财务处理/dictionary.json)。

### 2. 支持按公司、报告期等维度查询

**已实现。** SQLite为权威存储，业务键包含来源、证券代码、报告期、报表类型和合并范围；索引和固定快照成员支持按公司、季度、因子查询。`query`返回结果，`explain`展示精确依赖、版本和NULL原因。

示例见[单公司单期查询](示例结果/财务处理/单公司查询.json)、[营收同比因子解释](示例结果/财务处理/因子解释.json)。在源码根目录复现：

```powershell
.\.venv\Scripts\python.exe -m finpipe demo --workspace output/面试演示
.\.venv\Scripts\python.exe -m finpipe query --workspace output/面试演示 --company 600519.SH --period 2025Q4
```

### 3. 组织年报、季报等不同报告期

**已实现。** 按自然年季度统一组织，年报对应Q4，半年报对应Q2。利润表流量按年初至本期累计保存，资产负债表为期末存量。

Q1累计值就是单季值；Q2—Q4单季值减去同年准确上一季度累计值。缺季度不跨行差分，同比严格关联四季度前，Q1环比使用上年Q4。时间处理见[timeutil.py](../src/finpipe/timeutil.py)，季度计算见[features/common.py](../src/finpipe/features/common.py)。不同期间类型在[字典](示例结果/财务处理/dictionary.md)中列明。

## 四、数据清洗与标准化

### 1. 异常、缺失与重复数据处理

**已实现，分别说明如下。**

| 环节 | 实际规则与处理 | 可查看的结果 |
| --- | --- | --- |
| 异常值 | 非有限数和不可解析值置NULL并标记invalid；总资产须大于0，负债与流动类金额不可为负；ROE超出±100%保留值并标记warning | [人工反例](示例结果/清洗反例.json)的坏数字、负资产、极端ROE |
| 会计勾稽 | 资产－负债－权益的差超过`max(1元, 总资产×1e-6)`时标记warning；计算比率与来源披露指标核对 | [人工恒等式反例](示例结果/清洗反例.json)、[真实质量与核对明细](示例结果/财务处理/quality.json) |
| 缺失值 | NULL、空串、破折号、未披露等保留NULL及原因；缺字段、缺报表、数学无定义分别记录；合法亏损不直接判成坏数据 | [人工未披露反例](示例结果/清洗反例.json)、财报CSV中的字段状态与原因 |
| 去重与版本 | 相同内容复用源/清洗版本；最新完整观察中的唯一版本作为当前内容，旧版本保留；同一扫描不同内容存在冲突时不猜顺序 | [重复运行验收](示例结果/运行验收.json)、[版本与更正测试](../tests/test_integration.py) |

清洗实现见[cleaning.py](../src/finpipe/transforms/cleaning.py)，版本选择见[source_records.py](../src/finpipe/source_records.py)。当前接口不能证明完整官方修订顺序，所以“最新”依据完整观察事实；不会仅按一个`UPDATE_DATE`字段排序后删除历史，也不会用旧好值覆盖新坏值。

### 2. 按实际发布日期对齐财务数据

**已实现时间字段与可用边界，明确区分历史PIT限制。** 保存公告/已知更新边界、实际观察、处理和发布时间。来源只有日期时，按上海次日零点保守放出；报告期不直接当作可用日期。

特征的可用时间包括全部依赖报表。消费时还考虑实际发布边界。默认回测`observed`按本系统实际已知信息；`publication_proxy`是显式选择的公告近似，仍保留真实观察/发布时间与“历史版本未核验”标识。

实现见[cleaning.py](../src/finpipe/transforms/cleaning.py)、[backtest/io.py](../src/finpipe/backtest/io.py)。实际字段见[因子解释](示例结果/财务处理/因子解释.json)与[回测信号](示例结果/分组回测/signals.json)。今天抓取历史财报不能自动保证其数值是当年原始版本。

### 3. 记录每条数据的清洗状态

**已实现。** `clean_versions`保存清洗身份、字段值、字段状态、原因、处理时间；`record_states`保存选中、冲突、缺失裁决；`quality_events`和`runs`记录质量事件及运行阶段。

本次从正式清洗版本导出[72条清洗日志](示例结果/财务处理/清洗日志.csv)，不是手工编造日志。三类财报CSV同时包含`record_status`、`quality_status`、`field_states`和`reason_codes`。人工反例另存，不加入真实统计。

## 五、特征生成

### 1. 盈利能力、成长性与偿债能力

**已实现15个财务特征。** 以下标识与实际注册表一致；完整公式、单位和依赖由代码生成[数据字典](示例结果/财务处理/dictionary.md)。

| 类别 | 因子标识 | 金融含义与口径 |
| --- | --- | --- |
| 盈利 | `roe_weighted_ytd` | 来源披露的累计加权ROE，百分数转小数 |
| 盈利 | `roe_change_yoy` | 累计ROE同比相对变化：本期/上年同季－1 |
| 盈利 | `roe_change_yoy_pp` | 累计ROE同比百分点差：本期－上年同季 |
| 盈利 | `net_margin_q`、`net_margin_ytd` | 单季/累计合并净利润÷营业收入 |
| 盈利 | `gross_margin_q`、`gross_margin_ytd` | 单季/累计（营业收入－营业成本）÷营业收入 |
| 成长 | `revenue_growth_yoy`、`revenue_growth_qoq` | 单季营业收入同比/环比 |
| 成长 | `parent_profit_growth_yoy`、`parent_profit_growth_qoq` | 单季归母净利润同比/环比 |
| 偿债 | `debt_asset_ratio` | 总负债÷总资产 |
| 偿债 | `debt_asset_change_qoq_pp` | 资产负债率环比百分点差 |
| 偿债 | `current_ratio`、`current_ratio_change_qoq` | 流动比率及环比倍数差 |

成长性“净利润”采用归母口径，净利率采用合并口径，两个概念不混用。增长率要求正基期，负/零基期、缺历史、非法分母保留NULL和原因。百分点差`0.02`代表增加2个百分点；流动比率保持倍数，不乘100。

### 2. 方便后续添加新特征

**已实现。** 每个因子一个目录，`factor.py`统一包含说明、公式、单位、依赖和`calculate(context)`；[registry.py](../src/finpipe/features/registry.py)显式登记，字典与计算共用同一定义。

可查看[营收同比因子完整文件](../src/finpipe/features/factors/revenue_growth_yoy/factor.py)。共用季度、增长率、可比性与NULL处理在`common.py`，纯计算不访问网络、数据库或文件。新增因子需登记、补独立金融案例并按口径变化维护公式版本；源码变更后重新构建EXE。具体步骤见[因子扩展说明](../docs/factors.md)。

### 3. 输出证券代码、报告期、特征名和数值的特征表

**已实现。** [features_long.csv](示例结果/财务处理/features_long.csv)与同名Parquet均含`security_code`、`report_end`、`feature_name`、`feature_value`，另带状态、原因、单位、版本与时间。示例有180个位置。

同时输出[features_panel.csv](示例结果/财务处理/features_panel.csv)与Parquet，按公司×输出季度完整对齐；NULL保留空位。金额、比率和时间字段按明确类型写Parquet，并回读校验。

## 六、附加项

### 1. 数据质量监控

**已实现。** 采集检查请求/返回/预期量与分页结构；清洗检查字段缺失率、非法率及金融勾稽；特征检查有值/NULL及原因；发布前执行质量门禁。相同范围与上一成功扫描比较行数和空值率变化，`health`检查来源、任务和快照。

实现见[quality.py](../src/finpipe/quality.py)、[monitoring.py](../src/finpipe/monitoring.py)、[ops.py](../src/finpipe/ops.py)。结果见[质量JSON](示例结果/财务处理/quality.json)与[HTML摘要](示例结果/财务处理/report.html)。告警包含范围、批次、阶段、下游影响与重跑提示，失败不伪装成功；尚未接外部邮件/消息通知服务。

### 2. 增量处理机制

**已实现。** 相同输入复用源、清洗与特征版本；改变公司在范围内重算，其他公司复用。高级`run --refresh recent`仅扫描最近四个输入季度，仍发布完整原范围，不能因刷新缩小结果全集。公式或规则口径变化触发必要重算。

本次[运行验收](示例结果/运行验收.json)实际进行了两次离线重放：第一次计算180个位置；第二次`NO_CHANGE`，新增源/清洗/裁决版本均0，计算0，复用180，保持同一快照。在线增量与同输入全量等价、变更与坏新版失效另见[集成测试](../tests/test_integration.py)和[来源时效测试](../tests/test_snapshot_freshness.py)。

### 3. 简单分组回测与报告

**已实现。** 选择因子后按值从低到高分五组，组内等权；下一交易日收盘进入，持有20个交易日，在非重叠窗口计算价格收益与净值。可配置因子、组数、持有期、费用和日期。

真实公开示例使用`roe_weighted_ytd`，十家公司、五组、20个有效持有窗口；来源请求区间是2023—2025年，实际有效持有为2024-05-07至2025-12-24，前期不足信号如实跳过。详见[回测报告](示例结果/分组回测/report.html)、[独立SVG](示例结果/分组回测/nav.svg)、[分组成员](示例结果/分组回测/memberships.csv)、[各组收益](示例结果/分组回测/period_returns.csv)。

图表有日期轴、净值轴、G1—G5图例及同截面等权参考。回撤仅在持有窗口端点统计，缺报价不删除成员或填价；不模拟撮合、停牌、涨跌停和现金分红。历史版本未核验，报告不作为严格无偏或可成交绩效证据。实现与口径见[backtest](../src/finpipe/backtest)及[回测说明](../docs/backtest.md)。
