# 数据接入实现与真实采集记录

记录日期：2026-10-13，日期按上海时区。本文只记录已执行的接入验证；金融清洗、特征发布与 EXE 的验收由各自实现报告记录。

## 维护入口

接入模块为 `src/finpipe/ingestion/`：`client.py` 负责串行请求及冷却，`archive.py` 负责证据与清单，`universe.py` 负责冻结股票样本。公共接口只有 `collect`、`load_manifest`、`select_universe`，不写业务数据库，不夹带财务公式。

主程序传入 `network` 配置中的 `interval/timeout/max_attempts/max_wait`。默认每次请求前至少等 1 秒、超时 30 秒、最多 3 次尝试、单次重试等待上限 30 秒。采集需要新的归档目录，已有清单绝不覆盖。

仅对 HTTP 408、429、500、502、503、504 和瞬态连接/超时做有限重试。HTTP 403 不重试，停止本次同源余项；证书等永久问题不反复尝试。`Retry-After` 支持秒数与 HTTP 日期，超过最大等待时记录 `retry_deferred/next_retry_at`，同源后续请求全部 `not_attempted`。短等待在同一会话内遵守；最后一次 429 也不会通过换公司继续请求而绕开限制。

所有收到的 HTTP 响应都先保存 `response.content` 字节，再判断状态和解析 JSON，不重新序列化正文作为原文。Requests 可能按 HTTP 内容编码解压，这里保存的是响应正文证据，不是线路抓包。每次有响应的尝试都保留其正文路径、SHA256、状态、观察时间与请求参数。

## 清单的完整性含义

`complete=true` 表示冻结计划中的公司、报表、期间范围都完成了结构合格的请求和完整分页，不等于每个理论业务键一定有数据。请求范围由冻结查询参数及页面范围元数据证明，不能从返回行反推“采集完整”。

同一请求组必须页数齐全、总数稳定、每页行数与 `pageSize` 一致、合计等于 `count`，完全重复的行会判为分页异常。行需要完整的声明字段、正确的证券身份与报告期；必要字段是否有值、公告时间是否可信、金额是否适合计算，则由清洗模块裁决。这样不会在接入阶段过滤最新坏值而意外继续使用旧值。

个别未返回业务键进入 `missing_keys`，由主流水线用保守分母做覆盖率门禁。字段结构错误、未完成分页、HTTP 失败和整批异常空保留错误并使清单不完整。`load_manifest` 重验原文摘要、重新解析每页、复核请求范围与分页，不信任缓存 `rows`，也不会改变观察时间。`capture_kind=synthetic` 必须明确标识，正式流水线默认拒绝合成来源。

三个完整报表名由 `catalog.REPORT_NAMES` 唯一声明：`RPT_F10_FINANCE_GINCOME`、`RPT_F10_FINANCE_GBALANCE`、`RPT_F10_FINANCE_MAINFINADATA`。名单接口使用 `RPT_LICO_FN_CPD` 的 `REPORTDATE`，不能与完整表的 `REPORT_DATE` 混用。

50 家以当前来源行业排除明确金融类别，沪深京约 4:4:2 分层，各市场按代码排序确定性选择，实际为沪 20、深 20、京 10。空行业不凭名称补齐。CPD 的实际响应没有 `ORG_TYPE` 或 `LISTING_DATE`；当前非金融分类不证明 2022 年每季都应披露，历史资格仍保留 `unknown`。

全量财报分别为利润表 789、资产负债表 775、指标表 789。47 个未返回键都出现在部分京市公司的早期季度，完整业务键原始覆盖率为 `2353/2400=98.0417%`；没有将这些键擅自排除分母或改成 `not_required`。最终可用率还须考虑清洗与金融口径，不能用原始覆盖率代替。

独立统计发现 47 个声明字段空值：指标表流动比率 15、加权 ROE 10、资产负债率 14、毛利率和净利率各 1；利润表营业收入、营业成本、合并净利润各 1；资产表流动资产、流动负债、权益合计各 1。空值保留，未补零。非空声明数值中未发现布尔或非有限数字；按真实观察时间检查 `NOTICE_DATE/UPDATE_DATE`，未发现缺失、非法、早于报告期或未来时间。此检查只是时间基本合法性，不能证明供应商更新等于正式财报更正。

三表实际均提供 `CURRENCY=CNY`、`ORG_TYPE=通用`。各页原文和本系统观察时间不可变，来源公告与更新时间不会在重放时被刷新。
