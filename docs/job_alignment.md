# 岗位要求与项目证据

本项目以[机试题目](../机试题目-金融数据处理与特征工程.md)为交付范围，以[岗位 JD](job_description.md)调整实现重点。JD 强调数据可信度和维护能力，因此质量、恢复、字典、版本与运行证据属于正式主线，不能只作为 README 中的未来设想。

当前已实现财报流水线、真实50家公司示例和Windows交付。下表用于说明JD与实现的关系，实际验收和明确限制以[交付记录](delivery_validation.md)为准；原始设计与独立审核保留用于追溯。

## 1. 五类岗位职责

| JD 权重 | 项目中落实的能力 | 面试时应能直接检查的证据 |
| --- | --- | --- |
| 数据可信度 30% | 契约规则、逐条清洗原因、期望集合、质量指标、发布门禁、四类风险告警及恢复关系 | 注入一次源字段变更、一次漏启动、一次静默空值、一次单位不匹配；从告警找到批次与原始字段，实际恢复下游并核验告警关闭 |
| 数据生产 25% | 限流/分类重试、分页完整性、不可变原始归档、规范化入库、公司粒度增量、失败会话恢复、固定快照导出 | 冻结运行计划、失败页与重试轨迹；同输入增量/全量对照；重跑不重复增版本；请求量及实际耗时 |
| 基础数据与字典 20% | 三类非金融企业财报、稳定业务键、字段单位/时间/适用性、来源差异和人工核对 | 可查询的规范表、随发布的字典；两家公司原始年报核对；银行专用报表与通用报表差异的真实诊断证据 |
| 衍生数据与时点 15% | 15 个财务特征、冻结样本季度面板、来源观察与更正追踪、处理版本及依赖解释 | 独立手算、准确跨期输入；有效→无效→恢复；实际已发布时点审计、真实首次观察边界和历史限制 |
| 源接入与变更 10% | 来源适配器、字段契约、 schema/单位漂移检测、修映射后离线重放 | 改名/类型变化 fixture，失败上下文；新 profile 的重放结果与旧版本并存，不伪造源端更正 |

这些权重用于投入优先级，不机械拆成五个独立系统。采集、字典、质量和版本共用同一条生产链，避免重复落库和重复维护。

## 2. 技术要求的具体落点

| 要求 | 采用方式 | 评价依据 |
| --- | --- | --- |
| Python 工程 + Pandas/NumPy | CLI 与职责包；纯计算函数做清洗、季度还原和特征；数据库/网络交给边界模块 | 模块依赖清楚，异常分类、配置可验证；金融公式有独立预期值，未把所有过程放入一个脚本 |
| 关系型数据库 | SQLite 本地部署，唯一约束、外键、编号迁移、索引查询、事务发布与 backup API | 真实 DDL、时点/血缘 SQL、`EXPLAIN QUERY PLAN`、规模和耗时；恢复后的完整性核验 |
| 列式存储与 PyArrow | 显式 schema 的 Parquet 财务表、长表与面板；SQLite 是权威，Parquet 是固定发布快照 | 类型/NULL/单位/版本元数据可检查；与 SQL/CSV 一致；列投影、过滤和文件数的实测 |
| 分区与性能 | 小样本每表一文件；扩量后根据查询采用报告年度粗分区 | 记录文件数、大小、行组、读写耗时；不用公司×季度×因子制造小文件 |
| 数据认知 | 冻结 50 家、16 期输入、12 期输出；理论源键 2,400，特征格 9,000，缺失有原因 | 实测成功/缺失/不适用/未知资格数量、修订量、总耗时、下游清单、字段变更影响面 |
| AI-agent 协作 | 首轮四方评审及第二轮独立业务/金融/工程复审；主负责人统一裁决和命名 | 冻结基线、问题反例、采用/延后理由、v3契约与实际验证；中文注释规范，全量与增量不虚报验证 |
| 可维护交付 | 离线演示、EXE、源码、锁定依赖、字典、维护手册、失败恢复与备份 | 在无 Python、断网的 Windows 环境运行；中文/空格路径、参数错误、锁冲突均有明确行为 |

SQLite 可以展示关系建模与 SQL 能力，不能据此宣称已经验证 PostgreSQL/MySQL 生产性能。文档应说明可迁移边界；本次不为展示技术名词额外部署第二套数据库。

## 3. 范围控制

第一版完整覆盖题目规定的财报链路及上述维护能力。期货主力映射、复权、涨跌停、交易日历、期权、公告全文解析、多数据源对账、分布式调度均不属于这道题目的必需数据产品，不能添加没有数据与验收的占位模块。

财务原文及同源核对、转换/派生/输出对账属于主线，独立供应商平台与盘中逐笔接入尚无数据证据。本次已补[监控与核对](monitoring_reconciliation.md)契约：任务健康与数据健康分开，实时拓展按交易状态、序号域、时延和补包能力单独验收，不能将批处理设计宣传为已处理行情。

扩展新财务来源、新字段、新规则、新因子是第一版就要验证的维护路径。资产类型扩展留到真实业务需要，并单独定义交易规则和字典。Dask、远程数据库或流程平台只有在测量证明当前单机方案有瓶颈时引入。

可选分组回测有独立条件：真实行情、可核验的历史时点输入、交易日历与收益定义。可以用明确标注的模拟样例验证算法；不能用今天抓到的旧财报拼出声称无前视偏差的历史绩效。核心财报项目完整交付不依赖这个选做项。
