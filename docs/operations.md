## 1. 一份冻结计划与一个执行器

RunPlan 固定绝对工作区、输入方式、scope/universe、输出及上下文范围、profile、输入清单、请求排序、期望键、限速冷却、代码版本及预期父 head。run、demo、replay 构造计划，resume 读取原计划，随后共用相同处理、门禁和发布阶段。新 profile 或新范围必须新 run，不能靠修改 TOML 改旧失败任务的含义。

run 的终态为 SUCCEEDED / FAILED / BLOCKED / INTERRUPTED / SUPERSEDED，阶段游标为 COLLECTING / PROCESSING / VALIDATING / EXPORTING / ACTIVATING。阶段不承担发布事实，关联 snapshot 的 PUBLISHED 是唯一发布结论。结果另列 NO_CHANGE、PUBLISHED、PUBLISHED_RECEIPT_PENDING、PARTIAL_INPUT 等，不把进度状态与成功指针复制成两套权威。

真实输入及状态/profile 完全未变时复用成功快照并记 NO_CHANGE。实际业务更正、坏状态、补缺或新 profile 形成候选。终止记录、每次恢复及 HTTP 尝试保留；更新任务进度不抹去原失败证据。

## 2. 采集任务、分页与冷却

业务批次为来源×报表×准确报告期×代码分片。代码分片大小先在完整采集器实测，单公司请求是可靠后备；不预设 20 公司过滤已经可用。默认首次全输入范围，日常最近 8 季及未完成任务；--refresh all 显式深扫，报告重叠外更正不可自动发现的限制。

每次 HTTP 尝试精确到 batch/task、page_session、page_number、attempt。成功尝试保存原文、摘要、响应状态及时间，失败保存错误和下一次可请求时间。source_pages 是成功归档的视图/定位映射，来源观察关联真实尝试与行位置。

连接复用、明确 UA、显式超时、低频串行请求。403 不重试，业务/结构错误不盲目重试；瞬态 HTTP/网络错误有限退避。Retry-After 秒数或 HTTP 日期作用于同一来源的全部未完成任务；冷却超预算则延后退出，不能立刻换同源任务绕过限流。

页恢复先验证总数、键、页摘要和分页会话一致性。源边界改变时整批重新捕获，保留旧尝试但不拼接为完整新扫描。接口无远程 snapshot token，跨页一致性只能检测并有限重试。漏页、重复页、数量不匹配、身份不可解析、无法解释的整批空响应阻断完整候选。empty_expected 必须有真实不适用/未上市等证据。

请求任务数、耗时、重试和完整扫描/重叠扫描预算按首次实测校准，调度超时由任务清单及预算生成；未测前不宣称 60 分钟足够。

## 3. 指标与质量门禁

指标固定分子、分母、维度、排除证据和零分母行为，定义见数据契约。至少报告计划/返回/可识别/有效业务键、资格未知、隔离、原始与唯一行数、NULL原因、源财务/元数据变化、处理重建、因子求值及数值/状态/血缘变化、耗时、字节、文件数、峰值内存。

新鲜度分开记录最近尝试、成功访问、完成计划、观察到值变化、最新报告期、公告/更新事实。旧财报长期不变属于正常情况；任务是否漏启动、请求连续失败和明确应到报告缺失才是相应风险。字段 NULL 转换和有效配对变化单列。

| 门禁类型 | 默认动作 |
| --- | --- |
| 请求计划未完整、漏页、整批异常空、身份契约漂移 | 阻断候选，保留证据和定向恢复计划 |
| 业务键/因子唯一性、profile/血缘、字典或文件摘要不一致 | 阻断，不平均、不静默去重 |
| 保守可用报表覆盖 usable/(eligible+unknown) < 95% | 阻断完整发布；有证据 not_required 才能排除 |
| 必需适用字段 invalid 率 > 1% | 阻断；逐字段/表给分子分母，不能用总表量稀释 |
| 与可比较成功基线的行数下降 > 20% 或空值率增加 > 5 个百分点 | 阻断并核验范围、源契约及覆盖；不可比较另说明 |
| 单键可定位 conflict、字段缺失/异常或已知不可比 | 相关因子 NULL及告警，其他合法结果可进入候选；同时受以上预算约束 |
| 极端但可能真实的财务比例 | warning 保留，不统一裁剪；配置可定义更严格预算 |
| 纯展示元数据变化 | 审计记录，不自动制造金融冲突或告警风暴 |

阈值是首次工程配置，不是所有行业的金融定律；校准或修改参数生成新规则指纹/profile。规则 severity 表达风险，gate_action 表达是否阻断，不从 conflict 标签自动推导全局阻断。未核验同口径假设和独立已验证覆盖分别列示。

财务核对逐层保存键覆盖、规范转换、勾稽、同源指标、独立原文、派生手算及SQL/文件一致性，复用现有事件/指标和证据。动态基线只取同范围可比较成功样本，记录样本量/版本；不足或MAD为0不得除零或冒充通过。字段update_policy区别事件驱动和周期，扫描成功与金融值变化分开。具体定义见[监控与核对](monitoring_reconciliation.md)。

零有效范围、保守分母为零不作为默认完整交付成功；需要改变声明范围时显式新 scope。请求完成率和条件覆盖再高，也不能替代保守覆盖。全局阻断保留旧发布产物，默认当前 query 返回 blocked/stale、原因及非成功退出码；--allow-stale 明确请求旧快照并标注滞后。固定历史快照不被当前失败抹去。

## 4. 四类风险与告警闭环

| JD 风险 | 定位内容 | 恢复方式 |
| --- | --- | --- |
| 源变更或中断 | source、表、task/page/attempt、状态、字段契约、原文 | 中断 resume 原计划；改映射后新 profile 离线 replay |
| 定时任务失败 | job、计划窗口、run、最后开始/成功、心跳、进程与 OS 锁 | 独立 health 诊断；检查仍存活进程，恢复中断任务或启动新 run |
| 静默错误 | 覆盖、空值、异常、恒等式、同源及原报告差异 | 依赖定位并补采/深扫/重放，核验新发布结果 |
| 口径混乱 | 表字段、单位/币种/合并证据、字典与 profile | 修正规格、声明新版本，重放并保存旧快照 |

告警必须含 alert/event ID、来源/表/字段、run/batch/page/attempt、准确公司及期间、规则与参数、实际/阈值及分子分母、原始路径/行、影响因子/下游、建议可复制命令和恢复关系。无业务键时保留原页位置，不捏造代码。

告警状态 open → acknowledged → resolved；确认只表示已看到，不能解除。恢复运行、规则复查、成功下游发布及范围覆盖均核验后才 resolved。每次恢复关联原 alert 和 run，保留全过程。重复同问题按稳定规则/范围/计划窗口去重，新的业务状态与影响面仍能追加。过时候选 SUPERSEDED 不覆盖当前成功健康基线，也不能用旧失败重新宣布当前回退。

告警policy冻结检测窗口、连续次数、冷却、影响/时长升级及连续恢复窗口；硬错误立即失效，去抖只合并通知。静默、确认和一次正常采样都不代表恢复。外部接收方尚未配置，不宣称已发送。盘中行情需另外的交易/订阅状态、内容新鲜度、事件及接收时间、协议序号、积压和下游有效期；当前只读health不承担逐笔监控，扩展契约见上述核查。

## 5. CLI 语义与示例

以下命令以待实现的 finpipe EXE 为例；当前可运行探测工具见[README](../README.md)。源码版 python -m finpipe 使用同样参数。

~~~powershell
finpipe demo --workspace "F:\演示目录\财务样例"
finpipe run --config config/default.toml --workspace "F:\财务项目\工作区"
finpipe resume --run-id R1 --workspace "F:\财务项目\工作区"
finpipe replay --run-id R1 --profile P2 --workspace "F:\财务项目\工作区"
finpipe replay --from-db --scope S1 --profile P2 --workspace "F:\财务项目\工作区"
finpipe query --scope S1 --company 000333.SZ --period 2025Q4
finpipe query --scope S1 --as-of 2026-10-13T12:00:00+08:00
finpipe query --snapshot SNAP1
finpipe explain --snapshot SNAP1 --company 000333.SZ --period 2025Q4 --feature gross_margin_q
finpipe export --snapshot SNAP1 --output "F:\导出目录\SNAP1"
finpipe health --workspace "F:\财务项目\工作区"
finpipe alerts --workspace "F:\财务项目\工作区"
finpipe doctor --workspace "F:\财务项目\工作区"
finpipe backup --workspace "F:\财务项目\工作区" --output "F:\备份目录"
~~~

所有读/写入口支持统一 --workspace 或配置定位；上例省略时采用明确显示的默认工作区。replay 的 --manifest、--run-id、--from-db 恰选一个，均不联网或新增真实观察。profile 标签解析为已注册内容摘要，选择不明确时报错。demo 使用真实多期证据及独立 scope/workspace，不能把人工事件写到 live。

resume 使用原 RunPlan，失败请求只补必要任务并遵守同源冷却；恢复口径不变。父 head 不匹配的旧候选只记 SUPERSEDED，新处理使用当前 head 建关联新 run。SQL 已激活时只补回执/运行结果。rebuild 已合入 replay --from-db，首版不提供独立 research 命令。

query 默认当前健康结果；--snapshot 固定历史，--as-of 审计当时实际发布；--allow-stale 显式消费受阻后的旧发布。explain 展示精确输入及 NULL 原因。export 只导出固定已发布快照，不跳过门禁。doctor 默认只读诊断；--repair 在业务锁下仅补诊断、派生回执和已发布运行结果，不改金融值或绕过门禁。backup 用一致备份接口并核验产物。

错误码至少区分参数/配置、采集不完整、质量阻断、锁冲突/数据库忙、文件失败和过期候选；已发布但回执待修复输出明确结构化结果，不能说业务未发布。数值及最终代码在实现时冻结到唯一 CLI 规格和帮助文档。

## 6. 独立健康检查与调度

业务写入持本机 OS 排他锁，记录拥有者 PID、开始时间和工作区。心跳过期不能抢占仍被 OS 持有的锁；修复前核验进程，禁止仅删除锁文件强行启动。

health 不取得业务排他锁、不写业务库。它用有限只读查询检查计划窗口、开始/成功、心跳、库可读性、当前 head、完整快照及 stale，输出 JSON 和退出码。同 job/计划窗口/规则生成稳定 event_id，诊断保存在 diagnostics。数据库忙或损坏时标诊断不完整并非零退出，不能宣布健康、解除告警。

下一次取得业务锁的 run 或 doctor --repair 调用同一个幂等补入函数，把诊断按稳定 event_id 入库；不建立 health 的第二个写队列/第二套成功指针。重复检测同窗口只追加必要观测，不生成相同告警副本。

job 规格是周期、宽限和耗时预算的唯一来源；job manifest 与 Windows Task Scheduler 模板从它生成。采集任务与 health 分别由 OS 定时触发，二者不互相调用替代独立检测。若两者都未启动，项目无法自证故障，须检查 OS 任务历史或外部监督；文档明确这一边界。

计划任务使用绝对工作目录、隐藏后台窗口和日志路径。任务模板与 EXE 一起验收中文/空格路径、断网、未启动、僵持、重复检测和故障恢复。网络请求不在数据库写事务中，health 读取不等待到网络超时。
