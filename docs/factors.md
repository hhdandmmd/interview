# 因子目录与扩展

每个财务因子有一个同格式目录。公式、中文含义、准确期间依赖、单位、异常提醒和纯计算函数集中在该目录的factor.py；__init__.py仅公开定义。字典、财报计算与回测从同一个显式登记读取，回测不另外实现财务公式。

```text
src/finpipe/features/
  common.py                         # 准确季度、状态、血缘和共用安全运算
  calculation.py                    # 计算网格与版本指纹
  registry.py                       # 显式登记，保持输出顺序
  specifications.py                 # 从登记定义生成字典
  factors/
    revenue_growth_yoy/
      __init__.py                   # 公开FACTOR
      factor.py                     # 公式、依赖、单位和calculate
    roe_weighted_ytd/
      __init__.py
      factor.py
```

## 单一维护文件

以revenue_growth_yoy/factor.py为例：calculate(context)读取本季和准确lag4的单季营业收入，用共用ratio计算相对增长；FACTOR声明中文说明、公式`R_q / lag4(R_q) - 1`、依赖、ratio单位、成长政策及极端增长提醒区间。公式文本用于文档核验，程序执行Python函数。

FactorContext.read读取累计或期末值，quarter读取单季流量，offset按准确季度数回退。Q1使用累计；Q2—Q4仅减同年紧邻累计期。共用运算保留最新坏状态、缺值原因、不可比口径、真实输入时间和血缘；同一公司报告期内复用不可变读取，运行之间不缓存来源事实。

金额统一人民币元，比率以小数存储、展示为百分数；流动比率是倍数，负债率变化是百分点差。因子计算不调用网络、文件或数据库。已有十五项因子的规格、字典、数值和版本指纹保持原口径。

## 新增或修改因子

1. 复制最接近的因子目录，以明确英文标识命名。修改factor.py中的calculate和FACTOR，使名称、公式、单位、期间依赖、缺值政策及异常提醒一致。新增原始字段还需维护catalog和来源映射。
2. 在registry.py导入该目录并加入DEFINITIONS；不扫描目录、不执行用户公式字符串。重复名称直接拒绝。依赖声明决定所需历史，简单入口会为更长滞后自动向前扩展采集范围。
3. 补独立手算、缺失/非法分母、跨年与版本失效用例。声明依赖与真实血缘的契约测试会检查错表、错字段、错期间及遗漏依赖。
4. 新增因子或改变公式属于金融口径升级，必须更新formula_version及对应版本支持、冻结恢复和完整网格测试；保留旧口径的恢复能力。仅目录迁移不升级金融公式版本。不要改函数后继续复用旧口径缓存。

当前新增与升级流程是明确的代码修改及版本交付，保证依赖与公式可审核。

修改源码后使用源码入口验证；Windows EXE需重新执行scripts/build_windows.ps1构建，修改source目录不会改变已构建程序。

## 配置回测

根目录config.py的backtest.factors填写登记名称列表，每个选中因子独立分组、计算和出报告。财报主线仍生成全部登记因子。多因子共用一次行情采集与读取，并固定使用本次财报处理返回的同一snapshot。

运行后backtests/时间_编号/index.html为总览，每个因子目录保留独立HTML、SVG、成员/收益CSV和可复算输入。这里的因子输出目录是运行产物，与源码因子定义目录职责不同。
