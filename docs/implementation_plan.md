日期：2026-10-13。当前处于实现准备阶段，业务源码、数据库迁移和EXE尚未建立。本计划沿用v3金融、存储、监控和验收契约，不重新增加框架。实际完成状态以可运行代码和[验收记录](acceptance.md)为准。

## 1. 工作方式

采用一个主agent负责技术及交付，按阶段安排最多三个子agent并行。并行的是明确独立的工作，不要求任何时候占满席位。公共契约变化、发布顺序、集成和最终交付由主agent统一负责；主agent亲自写核心代码并审查全部变更。

单agent适合公共契约尚未稳定的纵向骨架、跨模块恢复协议及小修复；子agent适合接入、纯金融处理和独立验证。先形成可运行链路，再扩大并行范围。不能让各模块各自解释NULL、日期、profile和版本，最后再靠胶水代码统一。

## 2. 首批职责与文件所有权

下表为实施任务边界；模块和文件尚未创建，不作为已启动agent的清单。具体任务开始时进一步明确准确文件，禁止重叠写入。

| 角色 | 首批负责 | 首批不修改 |
| --- | --- | --- |
| 主agent / 技术负责人 | 项目安装与CLI骨架、共享规格/类型、配置/profile、物理迁移、存储、RunPlan、编排与发布；端到端集成 | 不把公开源语义或金融公式散落到编排中 |
| 数据接入agent | ingestion中的当前源参数、HTTP/分页/同源冷却、原文捕获清单；真实多期样例与来源证据说明 | 公共字段规格、数据库DDL、公式、业务发布指针 |
| 金融处理agent | transforms中的规范化、字段处理、准确期间/累计差分；features中的15公式及有限增量目标 | 网络、文件/数据库IO、profile定义、发布器；共享时间政策须按明确接口使用 |
| 验证agent | 人工手算与事件夹具、契约/金融/集成边界检查、缺陷报告；早期打包冒烟和最终运行验证按阶段进行 | 生产实现及公共接口；不以待测函数生成预期值 |

主agent拥有字段/状态规格与时间投影政策的唯一修改入口。子agent发现契约问题先给具体反例，主agent裁决和修改公共定义，再通知受影响模块；不写另一套同名常量或临时容错分支。

后续阶段可复用同一角色分配质量/导出、恢复/维护或性能核验，不一次启动十个专职agent。独立审核可以轮换已有agent的任务，审核者尽量未编写被审核逻辑；最后仍由主agent验证整体交付。

## 3. 开始并行之前的交接条件

主agent先确认：

- 证券/源业务键、字段类型与单位、NULL状态、错误类型及准确期间的代码表达。
- profile指纹与时间投影、真实来源观察和人工夹具身份；不能靠运行当前时刻补历史证据。
- 输入/结果和质量事件的最小明确结构，输出列及依赖引用；普通类型化结构即可。
- 数据库迁移、两类快照成员、单写锁、预期父head和发布可见性。
- 配置路径和绝对workspace解析、开发环境及真实可执行的最小命令。

契约只定义当下纵向链路所需边界，不预写未来通用基类、插件、字段缓存或任意DAG。首个版本用真实多期输入走通后，再根据实际重复拆分。需要修正的金融口径先明确，再实现相关公式。

## 4. 实施顺序与完成条件

| 阶段 | 分工及交付 | 完成门槛 |
| --- | --- | --- |
| 0：可安装骨架 | 主agent确定共享契约、配置及最小CLI/迁移；验证agent先准备独立手算 | 任意cwd可定位工作区；参数错误明确；公共类型/单位/状态一致 |
| 1：真实纵向链路 | 数据agent负责3家×8连续季度×3表及真实分页；金融agent负责规范化/15因子；主agent集成存储、门禁及固定产物 | 从真实捕获/归档到SQLite、CSV/Parquet、字典和解释；缺口如实报告；早期EXE冒烟可运行 |
| 2：正确性与增量 | 金融和验证agent核验跨年、坏日期、重述、补缺、冲突、A→B→A；主agent修正跨模块语义 | 每事件增量/同事实全量值、状态、时间和血缘一致；最新坏值不复活旧值 |
| 3：质量与维护 | 统一财务核对、覆盖/动态基线/告警、独立health、恢复和备份；按准确所有权分配 | 告警能定位并执行恢复；过候选不覆盖新发布；备份实际恢复成功 |
| 4：默认范围及交付 | 数据agent完成冻结50家及资格证据；验证agent独立执行安装、EXE和故障场景；主agent审核证据与文档 | A01—A13、A15—A16逐项有真实结果；可选A14如实声明；无Python断网EXE及中文路径通过 |

核心链路不等待全部模块“完成”才第一次集成。每批接入主线后运行相关检查，及时修正接口、真实源能力和打包问题。完整扫描/重叠扫描时间预算依据实测，不预先承诺固定分钟数或未经验证的批量请求。

盘中行情继续作为已定义的扩展范围：真实源协议、订阅、日历、序号/时间、补包和SLA未确定，不塞入财报首批实现，也不把离线人工回放写成真实盘中能力。

## 5. 子任务的下达与交付格式

每个任务必须写明目标、输入契约、准确可写文件、依赖、验收行为、禁止修改的共享边界和完成证据。交付至少包含：

1. 实际修改文件和可运行入口。
2. 通过/失败/未执行的相关检查及命令。
3. 真实来源与人工夹具的区别，未解决的具体问题。
4. 是否改变接口、规则、依赖、字典或性能假设。

子agent可以独立完成范围内代码与必要测试；跨边界改动由主agent统一处理。共享工作区中，同一文件同一阶段只有一个写入者；公共配置、依赖锁和迁移编号由主agent维护。需要隔离分支时采用独立checkout/worktree，不要求先引入协作平台。

所有自写代码注释/docstring、SQL、PowerShell及配置说明使用中文。维护者应该能从命名和简短注释看出口径、单位、边界及失败理由，不逐行堆注释。

## 6. 主agent的集成与最终审核

模块提交只表示局部完成。主agent检查金融口径和真实证据、跨模块状态传播、唯一键/血缘/profile、源冷却和分页、事务/文件恢复、当前健康消费、安装路径、依赖及打包，然后在实际端到端入口执行相关验收。

审核优先寻找可失败的业务反例，不只看代码风格或测试数量。局部测试通过不能替代真实多期采集、独立原报告核对、崩溃恢复和隔离EXE。每个新增抽象必须有当前重复问题支撑，发现重复规则及时回到唯一维护入口。

最终提交源码、可运行EXE、真实离线样例、规范表/特征、字典、质量/核对报告、恢复手册及实际验证记录。主agent负责让陌生维护者只凭README完成运行、解释一次NULL、恢复一次故障，而不是仅汇总子agent的完成声明。
