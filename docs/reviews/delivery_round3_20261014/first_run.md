## 缺口与最小修复

### F1：重复回测的错误没有给出操作方法，优先级P1

在交付根目录连续两次复制 `START_HERE.md` 的人工或真实回测命令，第二次均退出2，只给Windows文件系统错误。财务demo又明确可以重复运行，面试官容易把回测的行为误认为随机失败。

最小改动：创建输出目录前明确校验，中文说明“输出目录已存在，已有报告不会覆盖；请更换 --output 为新目录”。保留拒绝覆盖行为，在快速入口说明第二次复算换新目录。无需新增覆盖参数或报告版本管理。

### F2：错误工作区缺少路径与创建指导，优先级P1

复现：`finpipe.exe query --workspace "不存在 工作区" --company 600519.SH --period 2025Q4`，退出2，仅英文 `unable to open database file`。路径拼写错误、未执行demo、解压后工作目录不同，无法靠该提示区分。

最小改动：只读Store在库文件不存在时提供中文、解析后的catalog.sqlite绝对路径，提示先核对 `--workspace`，新工作区执行 `demo/run/replay` 后再查询。只读访问继续不创建目录或空库。真实数据库损坏和权限错误仍保留实际异常，不能统一伪称不存在。

### F3：双击入口没有准确报告路径，优先级P1

封存脚本成功退出0，但最后只打印 `%LOCALAPPDATA%/Finpipe/demo` 工作区；上方JSON的export_path还需要用户补 `report.html`。首次操作者需进入snapshots、识别UUID再打开。`START_HERE.md`也只有“打开snapshots中的HTML”，缺少直接路径或按钮。

最小改动：脚本保留CLI实际结果并从成功JSON的export_path生成准确报告路径，打印“复制此路径到浏览器或资源管理器打开”。不按目录修改时间猜最新快照，不自动联网，不改变业务结果。统一入口文档由主审核负责。

### F4：失败信息长且多重转义，优先级P2

限定单公司及一次重试的网络故障，run输出7339字符，alerts输出9154字符，health输出20851字符。request、attempt、原始异常全串进error，再串进payload_json，导致定位信息和恢复命令淹没在转义中。

已有完整事实和恢复逻辑，无需新建诊断系统。建议终端输出简短的中文失败摘要、run_id、具体manifest/checkpoint路径，完整请求上下文留在已有证据文件；alerts展示已存在的结构化payload即可。本轮不得把缩短展示解释为删除原始证据。
