# 全面交付审核与整改

日期：2026-10-14，版本0.1.3。三位独立评审分别检查业务/鲁棒性、首次运行、架构与体积，主审核复现、修复和集成。用户明确暂不加分红现金流，本轮不增加新业务命令、运行依赖或通用框架。原财报证据、真实观察时间和旧交付ZIP保持不变。

## 原题与交付判断

原题的公开采集、结构化存储、异常/缺失/版本处理、发布日期对齐、清洗日志、盈利/成长/偿债特征及源码/文档/EXE主线均有实现与实际数据。附加质量、增量及简单五组研究也已实现。逐项对应见[要求对照](requirements_traceability.md)，实际执行与环境见[交付记录](delivery_validation.md)。

0.1.2虽有191项回归，独立反例仍发现输入与展示缺陷，所以不能以旧测试数量代替交付结论。以下是本轮真实问题及最小整改；最终通过只以末尾的完整回归和新包实测为准。

## 是否过度设计

当前没有分布式调度、插件注册、通用Repository、公式解释器或任意DAG。版本与观察、清洗与裁决、精确依赖、候选与SQL发布头、指标与告警各自应对已复现的真实问题；压成几张可覆盖表或一个文件会丢失最新坏版、历史审计、增量等价及恢复语义。

它比最小机试脚本复杂，属于用户要求的可维护工程版本。0.1.2业务源码约281KiB；本地release约3GB主要是多个历史版本目录和ZIP，output约0.9GB是验收工作区，均不作为一个整体提交。原ZIP中EXE及依赖占大头；重复官方PDF单项约10.29MiB可削减，回测真实输入/报告约650KiB。

本轮删除无效配置，提取普通质量记录函数，使主编排阶段更清楚；候选记录改为一次source_id索引查找，消除逐状态扫描全记录的平方复杂度。保持原事务、阶段、父head和恢复语义，不引入新层次或基类。其他长函数仍是维护关注点，当前没有可复现正确性缺陷，不为了缩短行数全面重构。

## 面试官的操作路径

根目录双击START_HERE.html即可查看预生成真实财务/近似回测，随后进入windows/finpipe双击run_demo.cmd运行，窗口显示结果HTML准确路径。固定小财务库使用examples/financial，真实回测使用examples/backtest_real，避免随机备份ID增加复制成本。

源码、原题、当前使用与技术说明、要求对照、测试和许可证集中在source。50家公司完整财务结果可由随包公开原文重放，不附100MB完整SQL库。回测输出用新目录，已有结果不覆盖。进阶命令和故障恢复保留在[维护说明](implementation.md)。

## 保留限制

公告近似回测未核验完整历史财报版本、PIT股票池和可成交性，后复权报价未逐事件核验分红，不称无偏或税后总回报。真实盘中、其他资产、外部告警与生产任务注册不纳入本题完成率。独立干净Windows VM、OS级断网、Python3.11和物理磁盘故障仍未验证。
